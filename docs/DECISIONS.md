# DECISIONS · Pre-answered questions
Check here before asking the founder. Add a numbered line when a new decision is made; never rewrite history, supersede it.

## Product
- **D1.** We build **Parampara** (selected idea, Challenge 3). The wider Namma Shaale vision (Kannadi, Hejje) appears only in the roadmap and the `/how` page. Rules require continuing the selected submission.
- **D2.** Impress where judged, keep simple where not. Production grade: the AI layer, guardrails, evals, UI and UX, README, the judge's hour, offline behaviour. Demo grade: admin tooling, multi district tenancy, notifications.
- **D3.** Web app (PWA), not a native app. Evaluators prefer a web link; teachers install it to the home screen.
- **D4.** Four roles: teacher, master teacher, reviewer, officer. Each has a demo login and a one tap entry on `/`.
- **D5.** No leaderboards, points against colleagues, or any report naming a teacher. Delight is private (Law 6).
- **D6.** Every generated artifact (cards, answers) is stored in Kannada and English.
- **D7.** Real field data and sample data are separated by an `is_sample` flag and labelled in the UI (Law 7).
- **D8.** Mascot Hanate is an SVG component animated with Motion. Rive is a later upgrade.
- **D9.** Licence: Apache 2.0 at submission (government friendly, patent grant). The repo stays private until 30 Oct, then goes public.

## AI
- **D10.** Sonnet 5.5 for reasoning roles, Haiku 5.5 for fast roles, no Opus in the product.
- **D11.** Retrieval is LLM ranking over a cached card index after a deterministic prefilter. No embeddings provider, no vector DB until the library passes about 1,000 cards.
- **D12.** Speech is Sarvam (Saaras v4, Bulbul v3, `kn-IN`). If speech fails, text input and text answers keep working.
- **D13.** The hackathon Claude key is used only by the product and evals. Coding uses the founder's own Claude.
- **D14.** Caps: total $350, daily $25, 30 questions per session per hour.
- **D15.** Long jobs (card extraction) run in a route handler with an extended max duration and a `jobs` table the UI polls. No queue service.

## Data and auth
- **D16.** Supabase hosted project for dev and prod (no local Docker stack, to avoid clashing with other projects on this Mac). Migrations live in `supabase/migrations/`; applying them is a human key turn (`ALLOW_DB_PUSH=1`).
- **D17.** Field teachers join through an invite link (Supabase anonymous sign in bound to an invite code; no passwords, no phone OTP). Reviewer and officer use email OTP. Demo roles use seeded demo accounts.
- **D18.** Audio lives in Supabase Storage, private buckets, short lived signed URLs.
- **D19.** No real personal data in the repo, ever. Seeds are synthetic. Field exports never get committed.

- **D37.** Invite links are bearer links (supersedes the anonymous sign in part of D17 and BUILD M1.3). Each invite owns one hidden auth user (`invite-<code>@parampara.invalid`, never mailed); opening `/join/<code>` signs that user in on the server with an admin generated one time token (`auth.admin.generateLink` then `verifyOtp`, no password, no email). Why: teachers open WhatsApp links in an in-app browser first and Chrome later, clear storage, or change phones; an anonymous session is lost each time, a bearer link is not. Anonymous sign ins stay allowed but grant nothing (no profile, no access). A reviewer can revoke a link.
- **D38.** Sample accounts change only sample rows. Every demo login and anyone a sample account invites is `is_sample`; RLS (`current_is_sample()`) and server actions refuse a sample account's write to a field row, so jurors can press every button without touching Koppal data. Column grants stop any account flipping its own `is_sample`, role or consent through the REST API.
- **D39.** Audio storage (research 23 Oct: Supabase Free caps each upload at 50 MB; a 60 min 16 kHz WAV is about 115 MB). The browser's 16 kHz WAV chunks (under 1 MB each) go straight to the speech route and are never stored; the speech route transcribes, redacts and writes segments. The original recording parts are stored as uploaded (up to 50 MB each) in `interviews/` for "Hear it from the master" playback; a larger part is still transcribed and the UI says plainly that its playback is unavailable. Teacher question audio is not kept at all (privacy by design).
- **D40.** Platform limits we design to (researcher, 23 Oct, sources in the M1 handoff): Vercel Hobby functions stop at 300 s (no extension; `after()` shares it) and bodies at 4.5 MB, so card extraction runs per window as resumable `jobs` driven by the page; Sarvam REST speech to text is 30 s per request and 60 requests per minute (PAYG), so the browser sends at most 2 chunks at a time and backs off on 429; Supabase auth rate limits are per IP and all our sign ins come from Vercel's IPs, so the founder raises "sign ins" and "token verifications" in Auth → Rate Limits before field testing; Sonnet 5.5 cannot switch thinking off (lowest is effort `low`), effort goes in `providerOptions.anthropic.effort`; helplines are Childline 1098 (plus 112 for immediate danger) and Tele-MANAS 14416.
- **D41.** `lib/audio` cuts chunks on a 5 ms grid and drops each part's sub millisecond tail (under 16 samples), so every chunk offset is a whole millisecond and exactly sample aligned for `segments.start_ms`. A chunk is flagged silent (server skips it) only with under 200 ms of voice, against a noise floor threshold held between -55 and -35 dBFS: wrongly skipping speech loses words, wrongly sending hiss costs one cheap request.
- **D42.** One structured runner (`ai/run.ts`) for every Claude role: budget check first, up to 3 attempts with the schema or validation problems fed back, then `needs_human`; one `ai_calls` row per attempt; every result carries a `span` for the trace. Modes: *replay* (no `ANTHROPIC_API_KEY` or `AI_REPLAY=1`) serves `evals/recordings/<key>.json`, re-validated, and a miss is `no_recording`; *record* (`LIVE_EVALS=1` or `AI_RECORD=1`) saves only calls that carry an eval `itemId`, so real interview text never lands in git; *live* otherwise. Card extraction runs one 10 minute window (1 minute overlap) per call with a 240 s time budget, so a retry never crosses the 300 s limit (D40). (23 Oct, M2 AI)
- **D43.** Speech goes through `fetch` in `ai/speech/sarvam.ts` only. Without `SARVAM_API_KEY`, speech to text serves a fixture only when the audio's sha256 matches `ai/speech/fixtures/<sha>.json`, else `SpeechNotConfigured`. Text to speech defaults to mp3 (about a tenth of wav on 2G); text over 2,500 characters is split at sentence ends and the parts joined (wav: PCM under one header; mp3: frames, with each part's ID3 tag and Xing/Info frame removed). Speech `ai_calls` rows cost 0 and put audio seconds (`transcribe`) or characters (`speak`) in `tokens_in`. (23 Oct, M2 AI)
- **D44.** `ai/safety/patterns.ts` (`patterns@v1`, Kannada and English; `patterns@v2` adds Hindi and diagnosis, D-ai-4) is a deterministic backstop behind prompts and the reviewer: a card whose advice (title, steps, materials, why) involves punishment, threats, withholding, shaming or bias is moved to `dropped`, never shipped; a card that may name a child is held back as `child_identifying`; a label triggers a rewrite retry; only explicit prohibitions count as negation ("never hit", ಹೊಡೆಯಬೇಡಿ, kept with a reviewer flag), so "not wrong to hit" and ಹೊಡೆಯದೆ ಇರೋಕೆ ಆಗಲ್ಲ still count as harm; harm described only in the problem field is kept with `sensitive_context`. Grounding: with speaker labels every step cites the master's own words, and a number in a step must appear in its cited segments. The "Hear it from the master" clip is only a cited, master spoken, unredacted segment with nothing harmful in it, because the original audio is played. (23 Oct, M2 AI, revised after the safety audit)
